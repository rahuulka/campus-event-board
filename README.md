## 📱 Overview

**Campus Event Board** is an Android mobile app built with Flutter and Firebase. Students can browse a live feed of campus events, post their own, RSVP to ones they plan to attend, and subscribe to push notifications for the categories they care about.

## 🔥 Firestore Data Model

```
users/{uid}
  ├── displayName: String
  ├── email: String
  ├── subscribedCategories: Array<String>
  └── createdAt: Timestamp

events/{eventId}
  ├── title: String
  ├── description: String
  ├── date: Timestamp
  ├── location: String
  ├── category: String
  ├── organizerId: String          ← ref to users/{uid}
  ├── imageUrl: String?            ← Firebase Storage URL
  ├── createdAt: Timestamp
  └── attendees/{uid}             ← subcollection
        ├── rsvpedAt: Timestamp
        └── status: String        ("going")
```

## 🔐 Security Rules

**Firestore** — `firestore.rules`
- Any authenticated user can read and create events
- Only the organizer (matching `organizerId`) can edit or delete their event
- Users can only read/write their own user document
- Any authenticated user can RSVP; users can only write their own attendee document

**Storage** — `storage.rules`
- Any authenticated user can read event images
- Uploads capped at 5 MB per file

## 🚀 Getting Started

### Prerequisites

- Flutter SDK (3.x+)
- Android Studio with Android emulator
- Firebase project with Auth, Firestore, Storage, and FCM enabled
- Node.js (for Firebase CLI / FlutterFire CLI)

### Setup

```bash
# 1. Clone the repo
git clone https://github.com/rahuulka/campus-event-board.git
cd campus-event-board

# 2. Install dependencies
flutter pub get

# 3. Configure Firebase (if firebase_options.dart is missing)
dart pub global activate flutterfire_cli
flutterfire configure

# 4. Run on Android emulator
flutter devices
flutter run -d emulator-5554
```

### Build APK

```bash
flutter build apk --release
# Output: build/app/outputs/flutter-apk/app-release.apk
```

## 🛡️ Defense Q&A

**Q: How does Firebase Auth session persistence work?**
Firebase Auth saves the token on-device. Our `authStateChanges()` stream in `main.dart` redirects unauthenticated users to the login screen before any Firestore data loads.

**Q: What happens in Firestore when a user RSVPs?**
`rsvpEvent()` writes a document to `events/{eventId}/attendees/{uid}`. A `StreamBuilder` on that subcollection updates the attendee count live with no manual refresh.

**Q: How do FCM notifications fire on a new event?**
A Cloud Function listens for new event writes, reads the `category` field, and sends an FCM message to `/topics/{category}`. Subscribers receive it even when the app is closed.
